# 评测集说明（data/eval/）

## 这是什么

`qa.jsonl` 是 RAG 检索评测集：40 道题，覆盖知识库全部 5 章（Q1 账号权限 / Q2 网络与 VPN /
Q3 邮件与办公软件 / Q4 打印 / Q5 密码与安全），每题都标注了**应该命中的条目**。

## 为什么要刻意"口语化"改写

题目**不是**照抄条目标题，而是改写成员工真实会说的话，例如：

| 条目标题（知识库原文） | 评测题（改写后） |
|---|---|
| 【Q2-05】VPN 拨号提示"错误 691：拒绝访问，因为用户名和密码组合无效"？ | 拨号的时候报 691，说用户名和密码组合无效 |
| 【Q4-08】打印机卡纸和面板报错代码如何处理？ | 机器卡纸了，面板上还跳出错误代码 |
| 【Q5-02】忘记密码时如何自助重置？ | 密码忘了，能不能不打服务台自己重置？ |

如果题目直接用标题原文，关键词检索会"抄答案"式地拿高分，评测就失去意义。
**现在的题目对纯关键词检索是不利的** —— 这正是我们想量化的东西：混合检索（含查询改写）
能不能在"用户不会用官方说法提问"的情况下把正确条目捞上来。

## 格式

每行一条 JSON：

```json
{
  "id": "e13",
  "chapter": 2,
  "question": "拨号的时候报 691，说用户名和密码组合无效",
  "expect_ids": ["Q2-05"],
  "expect_lines": [[465, 493]]
}
```

- `expect_ids`：期望命中的条目编号（判定时看片段正文里有没有 `【Qx-xx】`）
- `expect_lines`：该条目在 `data/knowledge_base.txt` 中的行号区间（判定时看片段行号区间是否重叠）
- 两个条件**满足其一**就算命中，避免"片段从条目中间开始、正文里没带编号"导致的误判

## 怎么跑

```bash
python scripts/eval_rag.py                  # 4 组配置的对比表
python scripts/eval_rag.py --limit 10       # 抽样快跑
python scripts/eval_rag.py --with-answers   # 追加答案级指标（拒答率 / 误拒答率）
```

结果打印到控制台，同时写入 `reports/eval_<时间戳>.json`（含每题的命中明细，便于定位失败案例）。

## 维护约定

- **改了知识库就要同步改行号**：`data/knowledge_base.txt` 一旦增删行，`expect_lines` 会失效；
  此时以 `expect_ids` 为准（脚本优先用编号判定）。
- 新增题目时保持"口语化"风格，**不要把条目标题原词写进问题**。
